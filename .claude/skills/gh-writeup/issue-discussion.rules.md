# Issue discussion

For an issue the user answers after a discussion round. No title. Read the posted thread first. The headline, then one block per disposition.

```
<headline>

## <disposition>

<answer>

<discussion: only on overflow, a table, or a code fence>

## Suggested directions for you to choose

- <direction>
```

- Headline: one or two friendly sentences to the author that answer their main ask. From the second round on, it also says what the earlier replies left unanswered.
- One block per point, or per group of points that share an answer. Blocks the author must act on come first, then acknowledgments and no-action answers.
- `<disposition>` is a sentence-case phrase naming the outcome, such as `Hold off on scoring-workflow changes` or `Approval already exists`.
- `<answer>` is one line: the ruling, or the ask. An acknowledgment opens with `Ack.`
- `<discussion>`: the reason with a permalink for evidence, what the author does next, or who decides. Also for a table, or a fenced block of code or log, either of which on its own justifies one.
- An accepted gap carries its proposal under the block as `### Problem`, `### Proposal`, and `### Validation`, at most 3 bullets each.
- Suggested directions: only options the user chose to offer, one bullet each, worded so the author can pick. Omit the section when there are none. An answer to a point never goes here.
